# Roothatch bounded task template

Not an execution authorization; fill before use.

## 1. Role, outcome and specification
Task/card, parent, exact role; accepted requirement; observable outcome; owner
approval and execution mode.

## 2. Inputs, outputs and acceptance tests
Concrete preconditions/fixtures; outputs/state; positive/error/refusal/regression
and preservation cases; actual commands/runtime witnesses and nonclaims.

## 3. Component and source scope
Repository/baseline/candidate; literal write frontier; relevant ordinary source;
one writer; reviewer source read-only; task-owned scratch and custody.

## 4. Permitted effects and exclusions
Exact targets/data/actions; prohibited operations and existing holds; preserved
model/account/tool settings; no authority by implication.

## 5. Security-checkpoint disposition
Required/deferred/not-applicable with reason; profile/target/trigger/effects;
status and withheld use. Functional and defensive acceptance remain separate.

## 6. Completion and escalation
Done/proof/cleanup; defects by requirement/location/reproduction/consequence;
task-shaped limits; parent integration and remaining owner gates.

## Parent check
Record `TASK_SCOPE_CHECK: PASS` only after all sections are concrete and the role
fits. Otherwise NEEDS_CLARIFICATION and resolve the specific gap. A template,
assignment or generated token is not owner permission.
